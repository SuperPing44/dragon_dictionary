# Local SQLite and files on disk, no server

Dragon Dictionary is used by one person on one laptop, so it stores everything locally rather than in a hosted database: one SQLite file accessed through better-sqlite3 and Drizzle ORM, and uploaded files (PDF sources, later thumbnail drafts) as plain files with only their metadata in SQLite. Both live in `%USERPROFILE%\DragonDictionary\` (overridable with `DATA_DIR`), outside the repo so a re-clone or `git clean` can't delete them. This rules out access from other devices and needs no auth; reaching the app from a phone would mean revisiting this decision.

## Considered Options

- **node:sqlite**: no native dependency, but still a Release Candidate in Node and only supported by Drizzle's 1.0 RC. It is the upgrade path once both are stable, and the switch is a driver swap.
- **Prisma 7**: driver adapter, generated client and ESM changes add toolchain weight with no benefit at this scale.
- **libSQL**: built for remote/edge use, which a laptop-only app doesn't need.
- **Files as BLOBs in SQLite**: one file to back up, but the database grows with every PDF and streaming them is clumsier.

## Consequences

- With `cacheComponents` on, Next.js prerenders synchronous SQLite reads into the static shell, so every query goes through a `db/` module that calls `await io()` first.
- Server Actions cap requests at 1 MB, so uploads and file downloads go through Route Handlers.
- Migrations are SQL files generated by `drizzle-kit`, committed to the repo, and applied automatically at startup. The database runs in WAL mode.
- Never back up the live `.db` file by copying it while the app runs; use the backup API or `VACUUM INTO`.
