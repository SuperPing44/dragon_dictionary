# Dragon Dictionary – v3 Spec

> The build-ready spec for v3 of Dragon Dictionary: writing longer scripts comfortably. The decisions were made in one grilling session on 2026-11-09; there's no wayfinder map, since nothing needed research or a prototype.
> It builds on [`mvp-v1.md`](mvp-v1.md) and [`v2.md`](v2.md) (released up to `v0.5.0`) and only describes what changes. Anything not mentioned here stays as before.
> Concept and glossary: [`docs/CONTEXT.md`](../CONTEXT.md). Terms in **bold** are glossary terms.
> Status: **approved** on 2026-11-09. No mockups: the changes reuse the existing Script tab's look.

---

## 1. Scope

v3 delivers three script features. Each one is released on its own, in this order:

| Release | Feature | Section |
|---|---|---|
| `0.6.0` | **Emphasis**: bold, italic and underline in the script | §4.1 |
| `0.7.0` | **Full script** view, next to the existing **Sections** view | §4.2 |
| `0.8.0` | **Script PDF** export | §4.3 |

**Hard constraints** (`CONTEXT.md` §3, §7), unchanged: no AI features, no automatic research, no YouTube integration, single user, laptop only, English UI only, dark theme only. The **Script PDF** is printed black on white; that's a print layout, not a light theme.

**Out of scope for v3:**
- other formatting: strikethrough, headings, colours, highlight, font choice or size;
- Word-like pages in the editor: page sheets, page breaks or a page count while writing;
- moving the cursor from one section into the next with the arrow keys in **Full script**;
- a generated `.pdf` file download, or any PDF library;
- other exports (Word, Markdown, plain text);
- speaking time, sources or other project fields in the **Script PDF**.

## 2. Runtime and storage

- **No new dependencies.**
- **Script storage:** unchanged. Each section is still its own Tiptap JSON document ([ADR 0002](../adr/0002-script-text-stored-as-tiptap-json.md)); emphasis is stored as the standard Tiptap marks `bold`, `italic` and `underline` inside it.
- **Schema:** the shared script schema (`frontend/src/lib/script-schema.ts`) turns off `strike`. Bold, italic and underline are already part of StarterKit and stay on. Lists stay as they are.
- **Existing data:** a section that already holds a `strike` mark must still load. The mark is dropped and its text kept, either by a one-off migration or when the section is parsed.
- **`app_meta`:** one new key (`0.7.0`), the script view last used: `sections` (default) or `full`.

## 3. Shared rule: emphasis is everywhere the script is shown

Bold, italic and underline mark how a passage is spoken. They show wherever the script text is shown:
- the editor, in both views;
- the **Teleprompter**;
- the **Script PDF**.

They don't change word counts, speaking time or the **B-roll list**.

## 4. Features

### 4.1 Emphasis (`0.6.0`)

- **Shortcuts:** Ctrl+B, Ctrl+I, Ctrl+U toggle bold, italic and underline on the selection, or for the text typed next.
- **Toolbar:** **B**, **I**, **U** buttons in the writing-area header of the Script tab, left of ▷ Teleprompter. A button is shown active while the cursor or selection has that mark. Each button has a tooltip with its shortcut.
- **Sticky:** the writing-area header (with the toolbar, ▷ Teleprompter and Image) stays visible at the top of the script column while scrolling a long section.
- **Stage directions** can't be formatted; they keep their own look.
- **Strikethrough** is gone: Ctrl+Shift+S does nothing, and old strike marks are dropped (§2).
- **Teleprompter:** shows bold, italic and underline at its large text size.

### 4.2 Full script (`0.7.0`)

The Script tab gets two views, switched by a toggle in the writing-area header:
- **Sections**: today's view, one section at a time, picked in the outline.
- **Full script**: every section one after another in a single scrolling column, in outline order.

**Toggle**
- A two-option toggle, **Sections | Full script**.
- The editor opens in the view last used, remembered across all projects (`app_meta`, §2). The very first time it's **Sections**.

**Full script layout**
- A centred column of reading width, like a page in a word processor, without page sheets or page breaks.
- Each section starts with a heading: its section kind's name ("Hook", "Intro", …), or a subsection's title. Subsections follow the Main part, as in the outline.
- **Section-kind headings** can't be edited. **Subsection titles** can be edited right in their heading, saved like the outline's title field.
- Each section's text is its own editor, saved on its own as today. The arrow keys don't cross from one section into the next; clicking does.
- Empty sections show a placeholder, so they can be typed into.
- The B/I/U toolbar and shortcuts work in whichever section has the cursor.

**Outline in Full script**
- The outline stays, with its word counts and speaking time.
- Clicking an entry scrolls to that section's heading.
- Adding, removing and reordering sections work as in **Sections**; the column follows.
- The entry of the section the cursor is in is highlighted. If the cursor isn't in the text, it's the section at the top of the screen.

**Switching views keeps the place**
- **Sections → Full script:** scrolls to the section that was selected.
- **Full script → Sections:** selects the section the cursor is in, or the one at the top of the screen.

**Teleprompter**
- In **Full script**, ▷ Teleprompter starts at the section the cursor is in, or the first section if the cursor isn't in the text.
- In **Sections**, it still starts at the selected section.

**Unchanged:** the Image button inserts a **stage direction** at the cursor, in whichever section it's in. Jumping from the **B-roll list** to a stage direction opens that section in **Sections** view, or scrolls to it in **Full script**, with the same glow.

### 4.3 Script PDF (`0.8.0`)

**Button**
- An **Export PDF** button in the writing-area header of the Script tab, next to ▷ Teleprompter. It works in both views.
- It's disabled when the script has no text, like ▷ Teleprompter.

**How**
- The button opens a print layout of the script and the browser's print dialog. The user picks "Save as PDF" (or a printer) there. No file is generated by the app.
- The print layout is rendered from the saved section JSON with the shared script schema, as the teleprompter is.

**Content**
- The project title on top.
- Every section in outline order, each with its heading: the section kind's name, or the subsection's title. Empty sections are left out.
- Bold, italic and underline as in the editor.
- **Stage directions** inline, in grey italics, as "[Image: map of Scandinavia]".
- Nothing else: no speaking time, no sources, no other project fields.

**Look**
- Black text on white, whatever the app's dark theme.
- A readable serif body size for print, A4 by default.
- Page numbers at the bottom of every page.
- Sections run on, without forced page breaks; a heading isn't left alone at the bottom of a page.
- No app chrome: no sidebar, outline or buttons.

## 5. Spec-time decisions

- **One release per feature**, following the v2 pattern.
- **Emphasis is for speaking**, so it reaches the teleprompter and the PDF, not just the editor.
- **B/I/U only:** strikethrough is turned off; lists stay.
- **A toolbar as well as shortcuts**, so the formatting is discoverable.
- **Full script is a toggle, not a replacement**, so the focused one-section view stays.
- **No real pagination in the editor:** pages only matter for the PDF.
- **Storage stays per section** ([ADR 0002](../adr/0002-script-text-stored-as-tiptap-json.md)); the cost is that the cursor doesn't cross sections by keyboard.
- **The PDF comes from the browser's print dialog**, not a PDF library: no new dependency, at the price of one click in the dialog.
- **The PDF is a clean read or proofread copy:** script only, black on white.
