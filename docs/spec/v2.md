# Dragon Dictionary – v2 Spec

> The build-ready spec for v2 of Dragon Dictionary. It gathers the decisions made on the map [Map: Dragon Dictionary v2 spec](https://github.com/SuperPing44/dragon_dictionary/issues/28). Each section links the ticket that holds the full reasoning.
> It builds on [`mvp-v1.md`](mvp-v1.md) (released as `v0.1.0`) and only describes what changes. Anything not mentioned here stays as in v1.
> Concept and glossary: [`docs/CONTEXT.md`](../CONTEXT.md). Terms in **bold** are glossary terms.
> Status: **draft**, waiting for approval together with the Figma mockups. The archive mockups are still open in [Figma mockups: archive](https://github.com/SuperPing44/dragon_dictionary/issues/41).
> Design: [Figma mockups](https://www.figma.com/design/noDRCbSEOAeXATPnnjUqrJ/Untitled?node-id=10-1314), page *v2 screens*.

## 1. Scope

v2 delivers the four "Next" feature areas of `CONTEXT.md` §6. Each one is released on its own, in this order, and the spec follows the same order:

| Release | Feature area | Section |
|---|---|---|
| `0.2.0` | **Teleprompter** | §5.1 |
| `0.3.0` | **Video project fields**: **title options**, **thumbnail drafts**, **tags**, **description** with the **description footer**, **editing notes**, **B-roll list** | §5.2 |
| `0.4.0` | **Kanban board**, replacing the Video projects list | §5.3 |
| `0.5.0` | **Archive** | §5.4 |

**Hard constraints** (`CONTEXT.md` §3, §7), unchanged from v1:
- no AI features;
- no automatic research;
- no YouTube integration beyond a YouTube link entered by hand;
- single user, no auth;
- laptop only;
- English UI only, no i18n;
- dark theme only.

**Out of scope for v2:**
- teleprompter extras: a countdown, the remaining speaking time, retake markers;
- mirrored teleprompter text, second-screen output, remotes and foot pedals;
- a phone or any other device as a teleprompter remote, or access from other devices at all;
- any YouTube integration: uploading, statistics, comments or pulling data;
- a separate list view of video projects next to the Kanban board;
- a light theme.

## 2. Runtime and storage

Unchanged from v1 except for these points.

- **New dependency:** `@tiptap/static-renderer`, at the same version as the other Tiptap packages (3.32.0 at the time of research), for the teleprompter (§5.1).
- **Data location:** thumbnail drafts are stored next to the source PDFs, in their own folder:
  - `files/<source-id>/<file-id>.pdf` (unchanged);
  - `files/thumbnails/<project-id>/<draft-id>.<ext>` (new).
- **File transfer:** thumbnail uploads and downloads go through **Route Handlers**, like PDFs, since Server Actions cap at 1 MB.
- **Backups:** need no change. They already copy all of `files/`, so they include the thumbnail drafts.
- **Migrations:** each release that changes the schema ships its own `drizzle-kit` migration, applied at startup with a backup taken first, as in v1 (§3, *Migrations*).

## 3. Data model

Decided in [Settle the v2 data model](https://github.com/SuperPing44/dragon_dictionary/issues/42) and [ADR 0003](../adr/0003-found-tick-stored-on-the-stage-direction-node.md). Additions to the v1 model:

```
video_project     + description (text, default ''), editing_note (text, default ''),
                  + board_position (integer, order within its stage),
                  + youtube_link?, published_on? (ISO date text),
                  + final_thumbnail? → thumbnail_draft (cleared when that draft is deleted)
title_option      id, video_project, text, position, created
project_tag       video_project, text (as typed), position; unique (video_project, lower(text))
thumbnail_draft   id, video_project, original_name, ext, size, width, height, note?, uploaded
                  → files/thumbnails/<project-id>/<draft-id>.<ext>
broll_item        id, video_project, text, found, created
stageDirection    + optional `found` attribute in the section's Tiptap JSON
app_meta          + description footer, teleprompter speed level, teleprompter text size
```

### Fields

- **Final title option:** the **title option** whose text matches the project title, ignoring surrounding spaces, is the final one. There's no flag for it.
- **Tags:** unique per project, ignoring case, kept as typed, in entry order. Suggestions are the distinct tags across all projects; there's no shared tag table.
- **Final thumbnail:** a pointer on the project, so "at most one" holds by construction.
- **Found tick:**
  - **Script items:** the optional `found` attribute on the `stageDirection` node. A missing attribute reads as not found ([ADR 0003](../adr/0003-found-tick-stored-on-the-stage-direction-node.md)).
  - **Extra items:** `broll_item.found`.
- **Board order:** `board_position` orders projects within their stage. A project that arrives in a stage gets the top position, and the affected column is renumbered on each move. The archive doesn't use it.
- **Publish date:** `published_on` is a full ISO date (`2026-10-14`). The YouTube link and publish date are kept when a project leaves Published.
- **`app_meta` keys:**
  - the **description footer**, empty by default;
  - the teleprompter speed level, 8 by default;
  - the teleprompter text size, 56 px by default.

### Deletes

Additions to the v1 table:

| Deleted | Also removed | Kept |
|---|---|---|
| Video project | (v1 list) plus its title options, tags, B-roll items, thumbnail-draft records and thumbnail files on disk | the sources |
| Thumbnail draft | its record and its file on disk; the project's `final_thumbnail` if it pointed at it | — |

Files on disk are removed only after the database change succeeds, as for source PDFs.

### Migrations on existing data

For every existing video project:
- one title option is created from the title, so it's the final option;
- the description and editing note start empty;
- `board_position` is numbered per stage by `updated`, newest on top;
- a project already in Published keeps a null link and date. The archive shows it as "No date" and sorts it last.

Existing stage directions need no change.

### Idea → video project

As in v1, plus:
- one title option is created from the idea's title;
- the new project gets the top board position in Research.

## 5. Features

### 5.1 Teleprompter (`0.2.0`)

Decided in [Which browser APIs suit a keyboard-driven teleprompter?](https://github.com/SuperPing44/dragon_dictionary/issues/29), [Teleprompter behaviour and keyboard controls](https://github.com/SuperPing44/dragon_dictionary/issues/30) and [Teleprompter look and scroll feel](https://github.com/SuperPing44/dragon_dictionary/issues/31). Findings with sources: [`docs/research/teleprompter-browser-apis.md`](https://github.com/SuperPing44/dragon_dictionary/blob/research/teleprompter-browser-apis/docs/research/teleprompter-browser-apis.md) on the research branch.

The teleprompter is read straight off the laptop screen and controlled by keyboard only.

**Opening**
- **Button:** a **▷ Teleprompter** button in the writing-area header of the Script tab, left of Image.
  - Its tooltip reads *Starts at "<entry>" · Select another entry in the outline to start there*.
  - It opens at the entry (section or subsection) shown in the writing area. To start elsewhere, select that entry in the outline first.
- **Empty entries:** if the selected entry is empty, it starts at the next entry that has text.
- **Empty script:** if the whole script is empty, the button is disabled at 40% opacity with the tooltip "Nothing to read yet · Write something in any section first".
- **Opened state:** the click also enters browser fullscreen. The teleprompter opens **paused** with no countdown, and a key-hint panel shows until scrolling starts.

**What's shown**
- **Read-only:** there's no editing.
- **Headings:** section and subsection headings are small, muted labels. Subsections read "Main part · <title>".
- **Stage directions:** a small, dim amber inline pill, "◆ Image: <description>". The found tick (§5.2) isn't shown.
- **Empty entries:** skipped entirely, with no heading and no gap, and the jump keys pass over them.
- **End:** scrolling stops when a centred "— End —" reaches the reading line. It stays until you leave.

**Keyboard**

| Key | Action |
|---|---|
| Space | pause / resume |
| ↑ / ↓ | faster / slower, one speed level per press; holding repeats |
| ← / → | previous / next entry, paused at its start |
| + / − | text size, 4 px per press |
| Home | back to the top |
| Esc | in fullscreen, the browser exits fullscreen and the teleprompter pauses. Outside fullscreen, it leaves to the Script tab |
| F | enter fullscreen again |
| ? | show the key hint again, while paused |

- **Leaving:** returns to the Script tab with the entry you were reading selected.
- **Wake lock:** the screen is kept awake the whole time the teleprompter is open, paused or running, and released on leaving.

**Speed and size**
- **Speed:** levels **1–20**, where level *n* is 3*n* lines per minute, so the pace in lines holds when the text size changes. The default is **8**, which is 24 lines per minute. It's independent of the speaking-time rate.
- **Text size:** **56 px** by default, from **32** to **96 px**.
- **Memory:** speed and size are remembered app-wide in `app_meta`, across takes, projects and restarts.
- **Toast:** a change shows a short toast, such as "Speed 9" or "Size 60".

**Look ("Broadcast")**
- **Background:** near-black, the new token `bg/prompter` = `#050308` (`--color-prompter` in `globals.css`).
- **Text:** Inter semibold in `text/primary`, left-aligned, line height 1.35. The column is 17em wide, capped at the screen width minus 8rem, and centred.
- **Reading line:**
  - One third down the screen, a one-line band in `accent/primary` at 10%, with 40% top and bottom borders.
  - ▶ ◀ markers sit at both screen edges.
  - The line being read sits inside the band.
- **Fade:** a vertical mask fades the text out above the band (fully faded from 24% of the screen height up) and below it (starting at 70%, gone by 98%).
- **Sizes:** everything is sized in em, so the layout scales and the reading position stays put when the size changes.
  - headings: 0.32em, uppercase, tracking 0.18em, in `text/faint`;
  - stage-direction pills: 0.36em, in `amber` at 70% with a 30% `amber` border; they never split across lines;
  - the End marker: 0.4em, in `text/faint`.
- **Paused:** "❚❚ PAUSED" at the top centre.
- **Outside fullscreen:** "F: fullscreen · Esc: back to Script" at the top left.

**Implementation notes**
- **Scrolling:** a `requestAnimationFrame` loop moves one column with `transform: translate3d(0, -y px, 0)` (`will-change: transform`) inside an `overflow: hidden` viewport.
  - Each step is elapsed time × speed, with the frame delta capped at 100 ms so nothing jumps after Alt+Tab.
  - Position and speed live in refs, not React state.
- **Rendering:** `@tiptap/static-renderer` (`renderToReactElement`), not a read-only editor. `stageDirection` needs its own `nodeMapping`.
- **Fullscreen:** `document.documentElement.requestFullscreen()` is called from the click and from the `F` keydown. Its state is tracked with `fullscreenchange`.
- **Wake lock:** `navigator.wakeLock.request("screen")` on open, inside try/catch, and requested again on `visibilitychange`. `http://localhost` counts as a secure context.
- **Keys:** one `keydown` listener on `window`, registered with `useEffectEvent`.
  - Match keys on `event.code`, except + and −, which are matched on `event.key` because German layouts put them on different keys.
  - Call `preventDefault()` for the handled keys.
  - Skip IME composition and modifier combinations.
  - Allow `event.repeat` for speed and size, but not for play/pause.

### 5.2 Video project fields (`0.3.0`)

Decided in [Title ideas, tags and editing notes](https://github.com/SuperPing44/dragon_dictionary/issues/33), [Description with the source list](https://github.com/SuperPing44/dragon_dictionary/issues/34), [Thumbnail drafts](https://github.com/SuperPing44/dragon_dictionary/issues/35) and [B-roll list from stage directions](https://github.com/SuperPing44/dragon_dictionary/issues/36).

The **Publishing** tab shows **Title options** and **Tags** side by side, then **Thumbnail drafts** and **Description**, each at full width (Figma F1).

#### Title options

- **The project title is the final title.**
  - "Mark as final" sets the project title to that option's text. If the old title wasn't an option yet, it's kept as one.
  - The final option shows a gold ✦ **Final** badge and has no ✕.
- **Renaming:**
  - Renaming the project in the header also changes the final option's text, so it stays final.
  - If the new title matches a different option, that option becomes final, and the old one keeps its text.
  - Editing the final option's text in the list renames the project.
  - With no final option, a header rename only renames the project.
- **Matching:** surrounding spaces are ignored; otherwise the text must match exactly.
- **Starting list:** a project starts with one option, its title, already final.
- **List:**
  - Add with an input at the top (Enter).
  - Edit by clicking the text.
  - Drag to reorder.
  - ✕ deletes at once, with no confirmation.
  - Each option shows a length counter, such as `57/100`, which turns amber past 100 (YouTube's limit).
- **Duplicates:** adding or editing an option to the same text as another (ignoring case) is refused with the hint "Already an option".

#### Thumbnail drafts

- **Files:** PNG, JPEG, WebP or GIF, up to 20 MB each. Anything else is refused with a short hint.
- **Adding:**
  - by file picker (**Upload**) or by dropping files on the section, several at once;
  - by pasting an image with Ctrl+V anywhere on the Publishing tab. Text still pastes into fields as normal. A pasted image is named like `pasted-2026-10-27-1432.png`.
- **Duplicates:** there's no duplicate check.
- **Grid:** 16:9 cards in upload order, with each image fitted in, never cropped.
  - Each card shows the pixel size. It's amber, with "not 16:9", when the image isn't 16:9 or is smaller than 1280×720.
  - The last tile is a dashed drop target.
- **Final:** "Mark as final" gives at most one draft a gold ring and **Final** badge. No final is required, and marking another draft moves the badge.
- **Note:** an optional one-line plain note per draft, edited by clicking it, saved on Enter or blur. Placeholder "Add a note…".
- **Enlarged view:** clicking a card opens it over the dimmed page (Figma F2).
  - ← / → move between drafts, and Esc closes.
  - The bar shows "n of m", the file name, pixel size and file size, the Final badge or "Mark as final", **Download** (the original file under its original name), Delete and ✕.
  - The note can be edited below the image.
- **Delete:** ✕ on the card or Delete in the enlarged view, after the confirmation "Delete this thumbnail draft?" (Figma F2b). Deleting the final draft leaves the project with no final.

#### Tags

- **Chips:**
  - Enter or a comma adds a tag. Duplicates are ignored regardless of case, and tags are kept as typed, in entry order.
  - ✕ on a chip removes it, as does Backspace in an empty input (the last chip).
- **Suggestions:** while typing, tags used on other projects are suggested, with how many projects use them.
- **Copy:** copies all tags comma-separated (`norse mythology, ragnarok, fenrir`). A counter checks that string against YouTube's 500-character limit and turns amber when over. It's close to YouTube's own count, not identical.

#### Description

- **Your text:** plain multi-line text, saved as you type.
- **Live preview:** beneath it, a dashed, read-only preview shows exactly what Copy adds:
  - `Sources:` with the same `Title – link` lines as the Sources tab's source list, in link order, and the same "n linked sources left out for having no link" note;
  - the **description footer**, labelled "Footer · shared by all videos", with an **Edit in Settings →** link.
- **Copy description:** copies your text, the source list and the footer.
  - The parts are separated by one blank line, and empty parts are skipped.
  - With no linked sources that have a link, the `Sources:` heading is left out too.
  - The source list and footer are always included; there's no per-project switch.
- **Counter:** counts the whole copied text against YouTube's 5,000-character limit and turns amber when over.
- **Sources tab:** keeps its own source-list card and Copy, unchanged.

#### Settings and the description footer

- **Screen:** **Settings** opens from the bottom of the sidebar (Figma F4). For now it holds one card, **Description footer**.
- **Footer:** a plain multi-line textarea, saved as you type, with the placeholder "Channel links, socials, sign-off…".
  - It's added after the source list in every project's copied description.
  - Changing it changes every project's copied description.
- **Teleprompter values:** speed and text size aren't on this screen; they keep being remembered from use.

#### Editing notes

One plain multi-line note per project, on the **Editing** tab, saved as you type, like the idea note. No formatting and no checklist. Placeholder: "Cuts, music, pacing notes…".

#### B-roll list

On the **Editing** tab, next to the editing notes (Figma F3).

- **Script items:** a live view of the script's stage directions, in script order, grouped under section and subsection headings.
  - Editing or deleting a direction in the script changes the list at once. Descriptions are edited only in the script.
  - Directions with an empty description are left out. The same description at two places gives two items.
- **Extra items:** an **Extra** group after the script groups, for B-roll with no spot in the script.
  - One line of plain text each: add with "Add an extra item…", edit by clicking, ✕ deletes at once.
  - They stay in the order they were added.
- **Found:** every item has a checkbox; ticked items are dimmed.
  - The header shows a progress bar and "n/m found" across script and extra items.
  - A script item's tick is saved on its stage direction, so ticking saves that section ([ADR 0003](../adr/0003-found-tick-stored-on-the-stage-direction-node.md)).
- **Open in script:** clicking a script item opens the Script tab at that entry, with the direction highlighted by a brief glow (Figma F5). The direction is found by its entry plus its position among that entry's directions. Extra items have no link.
- **Copy list:** copies plain lines, such as `Hook: wolf eye close-up` and `Extra: drone shot of a fjord`.
- **In the script editor:** a found direction shows a small, non-clickable ✓ after its text on the amber chip.

### 5.3 Kanban board (`0.4.0`)

Decided in [Kanban board behaviour](https://github.com/SuperPing44/dragon_dictionary/issues/38). The board replaces the v1 Video projects list. Its screen title and sidebar entry stay **Video projects**.

- **Header:** "Video projects", the line "n in production · new projects come from the idea list", a title search and a category filter.
- **Columns:** **Research, Script, Recording, Editing, Thumbnail, Upload**. They fill the width with no sideways scrolling, and each column scrolls on its own.
  - Each column header shows the stage name and a count.
  - An empty column shows a dashed placeholder, such as "Nothing in Editing".
  - With no projects at all, the board's empty state repeats the hint that projects are created from the idea list.
- **Cards** (the **Board card** component):
  - a small 16:9 image of the **final thumbnail**, only when there is one;
  - the title, up to 3 lines;
  - category colour dots;
  - "≈ length · n sources".

  Clicking a card opens the project on the Script tab.
- **Moving:** drag a card between columns.
  - Moves are free: forward, backward or skipping columns, with no checks or warnings.
  - The stage stars on the project page stay and set the same stage.
  - There's no keyboard way to move cards; the stars are the alternative.
- **Order:** manual. Drag within a column to reorder.
  - A card that arrives in a column lands on top, wherever it's dropped. This applies to dragged cards, stage changes made with the stars, and new projects from the idea list.
  - While dragging, the target column is highlighted, with a line at the top and the hint "Drop anywhere — it lands on top" (Figma K2).
- **Publishing:** while a card is dragged, a gold dashed **Publish → Archive** zone appears at the right edge (Figma K2b). Dropping a card there opens the publish dialog (§5.4).
- **Filter:**
  - **Search:** a title search.
  - **Categories:** a popover with checkboxes; a card shows if it has any picked category.
  - **Matches:** non-matching cards are hidden in every column, and the counts show matches. The header reads "n of m shown · Clear filters" (Figma K3).
  - **Reset:** the filter resets when you leave the screen.
  - **Dragging while filtered:** within a column, a card is placed relative to the cards you can see.

### 5.4 Archive (`0.5.0`)

Decided in [Archive behaviour](https://github.com/SuperPing44/dragon_dictionary/issues/40). The **archive** is the set of projects in the Published stage; it isn't a new kind of record.

**Publishing**
- **Dialog:** dropping a card on the **Publish → Archive** zone, or clicking the seventh stage star, opens a small dialog with two fields:
  - **YouTube link:** optional, so it can be added later.
    - It must be an `http(s)` URL.
    - A link that isn't on youtube.com or youtu.be gets a hint but is still accepted.
  - **Publish date:** prefilled with today, or with the kept date when publishing again. Any date is allowed, including a future one.
- **Buttons:** **Publish** and **Cancel**. Cancel leaves the project where it was, which makes an accidental drop harmless. Publishing again prefills the kept link and date.

**Archive screen**
- **Sidebar:** the Archive entry sits after Video projects, with a count. With nothing published, the screen reads "Published videos appear here".
- **Rows:** newest published first (the **Archive row** component). Each row has:
  - a fixed 16:9 thumbnail slot: the final thumbnail, or the dragon emblem dimmed when there is none;
  - the title and its categories (colour dots and names);
  - the publish date;
  - ≈ length;
  - a link to the YouTube video, which opens in a new tab, or an amber **Add link** when it's missing.

  Projects without a date show "No date" and sort last. Clicking a row opens the project.
- **Filters:** a title search, a multi-category filter (any match, as on the board) and a year filter on the publish date. The year filter offers only years that have published videos. All three reset when you leave the screen.

**Published projects**
- **Editing:** fully editable on the normal project page.
- **Header:** the header shows the publish date and the YouTube link, both editable, and the back link says "Back to Archive".
- **Back to the board:** setting a lower stage with the stars puts the project back onto the board, on top of that column. Its link and date are kept.
- **Deleting:** works as for any other project.

## 7. Spec-time decisions

These weren't decided on a ticket. They were filled in when the spec was written, and they're confirmed when the spec is approved.

1. **Saving:** like v1, everything saves automatically.
   - Free text (description, editing notes, footer, draft notes) saves on change, debounced to about 1 s.
   - List actions (add, delete, reorder, tick, mark as final, move a card) save immediately.
2. **One migration per release:** the data model of §3 is split across the releases that need it:
   - `0.2.0` only adds `app_meta` keys and needs no migration;
   - `0.3.0` adds the field columns and tables, the final-thumbnail pointer and the title-option seed;
   - `0.4.0` adds `board_position`;
   - `0.5.0` adds `youtube_link` and `published_on`.
3. **Teleprompter route:** the teleprompter is its own page under the project (`/projects/<id>/teleprompter?entry=<section-id>`), so Esc outside fullscreen and the browser's Back both lead back to the Script tab.
4. **Dates:** publish dates show as "14 Oct 2026" and are entered with the browser's date input.
5. **Archive count:** the sidebar count for Archive is the number of published projects.
6. **Changelog:** every build PR adds its line under `[Unreleased]` in `CHANGELOG.md`. Each release turns that into a versioned section and tags `v0.x.0` on `main`, as the map's working agreement says.
